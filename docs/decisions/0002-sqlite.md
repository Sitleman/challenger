# 0002 — Хранилище: SQLite вместо Postgres

**Дата:** 2026-10-22
**Статус:** принято
**Issue:** #9

## Контекст

README закладывал PostgreSQL + sqlc + docker-compose. Первый кусок, которому нужно
хранилище, — подтверждение дня по `#task` (#9): одна команда, несколько человек,
десятки пруфов в месяц. Хранить состояние в самом закрепе нельзя: Bot API не отдаёт
сообщение по id, а для правила «≥2 уникальных реакции» нужно помнить, кто реагировал.

## Решение

SQLite в одном файле рядом с бинарём (`DB_PATH`, по умолчанию `challenger.db`):

- драйвер `modernc.org/sqlite` — чистый Go, без cgo;
- миграции — goose, лежат в `migrations/`, встраиваются в бинарь и накатываются при старте;
- запросы — sqlc с движком `sqlite` (`internal/db`).

Схема минимальная — три таблицы: `challenges`, `proofs`, `reactions`. Участники
выводятся из пруфов, статус дня вычисляется, реакции хранятся множеством
`(proof, user)` — повторно присланный апдейт ничего не ломает.

## Почему

- Деплой остаётся «один бинарь»: не нужен ни docker-compose, ни отдельный сервер БД.
- Для одной команды нагрузка ничтожна; конкурентных писателей — один процесс.
- sqlc и goose поддерживают оба движка: переезд на Postgres — это перенос SQL,
  а не переписывание кода вокруг.

## Следствия

- Бэкап — копия файла; `DB_PATH` на деплое должен указывать на постоянный диск.
- Пул соединений ограничен одним (`SetMaxOpenConns(1)`), чтобы не ловить `database is locked`.
- Мультикомандность (v3) или несколько инстансов бота — повод вернуться к Postgres.
- `go.mod` поднят до `go 1.26.0`: этого требуют актуальные `goose` и `modernc.org/sqlite`.
