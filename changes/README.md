# Изменения для пользователей

Каждый PR добавляет один или несколько файлов `<уникальное-имя>.json`:

```json
{
  "type": "feature",
  "text": "Теперь текущую версию бота можно узнать командой /version."
}
```

Типы: `feature`, `improvement`, `fix`, `internal`. Текст — короткий, на русском,
с пользовательским результатом и способом воспользоваться новой возможностью.
Для технического PR тоже добавить запись с `type: internal` и объяснением.
Она не попадёт в пользовательский список. Полностью технический выпуск получает
сообщение «Технические изменения, команды работают как прежде».

Существующие файлы не редактировать и не удалять: они входят в историю выпусков.
Отмена возможности — новая запись. При подготовке prod-релиза убрать из черновика
пункты отменённых до выпуска возможностей и объединить связанные пункты.
Автоматическая сборка группирует записи, убирает точные дубли внутри категории,
но не пытается самостоятельно понять смысл отмены или исправления.

Формат итогового сообщения — обычный текст Telegram, без Markdown/HTML.
Заголовок «🚀 Бот обновлён до vN» добавляется автоматически. Тело GitHub Release
содержит только текст под заголовком. Итог должен помещаться в 4096 UTF-16 единиц;
длинный выпуск нужно сократить перед аппрувом.
